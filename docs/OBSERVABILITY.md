# Observability, Telemetry & Drift Monitoring

---

## 1. System Observability vs. ML Observability

In production machine learning systems, healthy infrastructure does not imply healthy predictions. 
The fraud platform enforces dual-layer observability:

| Dimension | System Observability | ML Observability |
| :--- | :--- | :--- |
| **Focus** | Infrastructure health, availability, latency, throughput, errors. | Model prediction accuracy, score distributions, data drift, concept drift. |
| **Failure Modes** | Network timeouts, consumer lag spikes, OOM kills, 500 status codes. | Silent failure: Model outputting all 0s, shift in customer spend distributions, decaying recall. |
| **Key Metrics** | p95 latency, RPS/TPS, CPU/RAM, TCP pool exhaustion. | Population Stability Index (PSI), KS-statistic, Brier Score, calibration slope. |
| **Instrumentation** | Prometheus counters, histograms, Grafana dashboards. | Statistical distribution collectors, drift detection jobs, feedback monitors. |

All services expose telemetry on `/metrics` (or port `9100`):

| Metric Name | Type | Labels | Description |
| :--- | :--- | :--- | :--- |
| `transactions_processed_total` | Counter | `status` (`success`, `error`, `duplicate`) | Cumulative count of transactions processed by pipeline. |
| `fraud_predictions_total` | Counter | `model_version`, `model_type` | Total inferences generated by ML models. |
| `approved_transactions_total` | Counter | `policy_version` | Transactions triaged as `APPROVE`. |
| `review_transactions_total` | Counter | `policy_version` | Transactions triaged as `REVIEW`. |
| `blocked_transactions_total` | Counter | `policy_version` | Transactions triaged as `BLOCK`. |
| `prediction_latency_seconds` | Histogram | `step` (`features`, `inference`, `shap`, `risk`) | Millisecond latency histograms (buckets: 0.005, 0.01, 0.025, 0.05, 0.1, 0.25). |
| `kafka_consumer_lag` | Gauge | `topic`, `consumer_group`, `partition` | Unconsumed message backlog per partition. |
| `api_request_latency_seconds`| Histogram | `method`, `endpoint`, `status_code` | HTTP REST request latency. |
| `api_errors_total` | Counter | `endpoint`, `error_type` | Total HTTP 4xx and 5xx responses. |
| `calibrated_probability_gauge` | Histogram | `model_version` | Distribution of emitted calibrated probabilities. |
| `risk_score_distribution` | Histogram | `policy_version` | Histogram of final 0–100 risk scores. |

## 3. Grafana Dashboards

The stack provisions pre-configured dashboards in `monitoring/grafana/dashboards/`:

1. **Dashboard 1: Executive Fraud & System Operations**
   - Live TPS gauge vs. Capacity threshold.
   - Decision split pie chart (`% APPROVE`, `% REVIEW`, `% BLOCK`).
   - Hourly fraud rate % trend vs. Historical baseline.
   - End-to-end pipeline latency (p50, p90, p95, p99).
2. **Dashboard 2: Distributed Streaming & Backing Stores**
   - Kafka topic consumer lag per partition.
   - Redis memory utilization, hit ratio, and eviction count.
   - PostgreSQL connection pool status and active transactions.
3. **Dashboard 3: Machine Learning & Telemetry**
   - Real-time prediction distribution (binned probability histogram).
   - TreeSHAP feature importance ranking shifts over time.
   - Rule trigger frequency heatmaps.

## 4. Data Drift & Model Degradation Detection

### 4.1 Data Drift (Covariate Shift)
Occurs when the distribution of incoming features $P(X)$ shifts relative to the training distribution $P_{\text{train}}(X)$, even if the relationship $P(Y|X)$ remains constant.
- **Monitored Features**:
  - `amount` distribution (e.g., inflation or seasonal shopping shifts).
  - Geographic distribution (`country`, `city`).
  - Device distribution (new mobile OS releases).
- **Statistical Tests**:
  - **Population Stability Index (PSI)**:
    $$\text{PSI} = \sum_{b=1}^B \left( \text{Actual}_b - \text{Expected}_b \right) \times \ln\left( \frac{\text{Actual}_b}{\text{Expected}_b} \right)$$
    - $\text{PSI} < 0.1$: No significant distribution shift.
    - $0.1 \le \text{PSI} < 0.25$: Moderate drift; warning triggered.
    - $\text{PSI} \ge 0.25$: Critical drift; model retraining recommended.
  - **Kolmogorov-Smirnov (KS) Test**: Compares continuous cumulative empirical distributions $D = \sup_x |F_{\text{actual}}(x) - F_{\text{train}}(x)|$.

### 4.2 Concept Drift (Model Degradation)
Occurs when the underlying relationship between features and fraud $P(Y|X)$ changes (e.g., fraudsters devise a new attack pattern that bypasses existing velocity rules).
- Monitored by tracking **dispute/feedback latency** and evaluating sliding-window **Recall @ Fixed False-Positive Rate** once analyst ground-truth labels arrive.
